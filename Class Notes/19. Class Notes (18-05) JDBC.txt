- static blocks will be executed before the main method of our application.

- as soon as our application/Class loaded into the memory, static blocks will be executed. 

- whenever we try to create object of a class, then constructor of that class will be executed, but before executing the constructor if any non-static blocks are there then those blocks will be executed.

- non-static blocks will never execute if we don't create object.

- purpose of a static block is when we execute some code before main method we should write them inside a static block.

- purpose of an non-static block is with irrespective of a constructor  we need to execute some line of code, then we will use a non-static block.

JDBC:    Java Database Connectivity
====== ============================

--Java Mostly used in industry to develop Business application.

--common and general things required in a business application:

1. maintaining the business data permanently in a secure and easily retrieval manner.

2. processing the data according to the business rules.

3. presenting the data to the user in user understandable format.


--we store the business data for a typical business application inside RDBMS s/w.


Q/- Why Java-DB communication is required ?

A/-

RDBMS are excellent in data storage in a secure and easily retrieval manner, but it is very poor in processing and presenting the data in user-understandable format.

--Java is excellent in processing the data and presenting the data, but Java is very poor in storing the data 
(In Java we can store the business data permanently using Serialization and Files)

--so in order to develop a powerful business application we need to communicate our Java Application with the DB server.


Q/- How Java DB communication is possible ?

A/-

--Java App can do any task only through the method calls and objects, 
these method calls and object are not directly understandable to the DB s/w.

--DB s/w can understands only Sql, Java Compiler does not accept the sql syntax directly.

--Despite being heterogeneous platforms, Java and databases can communicate through JDBC.

Java -------- JDBC driver s/w -----------------DB s/w



- JDBC is a technology that enables any kind of Java application to communicate with any kind of DB s/w in a standard manner.

- JDBC technology is given by Sun-microsystem(Oracle Corp).

- JDBC technology comes in the form of a specification (It is a documentation which describes rules and guidelines to develop a particular s/w : "JDBC driver s/w").


- JDBC driver s/w is the implementation of the JDBC specification, which will act as a translator s/w to communicate Java App with the DB s/w.

--Each DB s/w have their own JDBC driver s/w, so DB vendor will implement the JDBC specification and they develop the JDBC driver s/w.

--these driver s/w comes in the form of a .jar file.

Mysql:   mysql-connector.jar

- JAR file works like "ZIP file" for Java programs.

- A JAR file is a compressed file that contains:

	.class files
	packages
	libraries
	metadata
	resources in a single file.

--compile all the .java files -----> .class files ----> zip all the .class files inside a .jar file

--all the JDBC driver s/w is developed according the same JDBC specification.




--in order to communicate our Java application with the DB server, Java developer need to get/download JDBC driver s/w and need to add the JDBC driver related jar file in the class path of our application.


--In order to communicate our java application with the DB server, Java Developer needs 2 things:

1.JDBC driver related jar file

2.JDBC API (this API comes in the form of following 2 packages):

1.java.sql
2.javax.sql

--this JDBC API contains all the library classes, interfaces using which we can communicate our java application with the DB server.

Note: JDBC API comes along with the JDK installation.


JDBC client:
==========

--In Java DB communication, our Java application will act as a client because Java application needs the services of DB server. so our Java app is a JDBC client.


Responsibility of the JDBC client:
===========================

1. Requesting the DB connection.

2. Submitting the appropriate SQL statement to the DB server in the form of String object.

3. Processing the result given by the DB server.

4. Dealing with exceptions if any.

5. Managing the transactions whenever it is required.

6. closing the connection once done with the DB operation.


JDBC driver:
==========

--it is a translation s/w written in Java according to the JDBC Specification
(it comes in the form of .jar file)

Responsibility of JDBC Driver :
=======================

1. establishing the connection.

2. receiving the JDBC method calls (java method call) and translate them into the DB understandable format (sql) and forward them to the DB server.

3. Translating the DB s/w given result in the Java format (Java objects) and returns that object to the JDBC client.


Steps to connect our Java application with the DB server (Mysql):
================================================================

1. download/get the JDBC driver related jar file (mysql-connector.jar) from the internet and set that jar file inside the class path of our java application.

2. Load the JDBC driver related main class into the memory.

3. Prepare the connection String.

4. Establish the connection

5. after performing the CRUD operation close the connection.

Problem or Limitations with Statement Object to update the data:-
================================================================
1. complexities to concatenate the dynamic variables.

2. whenever we pass any query to the DB using Statement obj, DB engine will perform following tasks every time to execute that query.

	a. query compilation
	b. query plan generation
	c. query optimization


--for the same query doing these operations every time, it will degrade the performance.


3. SQL injection  
- SQL Injection is a security attack in which malicious SQL code is inserted through user input to manipulate database queries.
- Or we can say that SQL Injection happens when user input changes the original SQL query behavior

-We need to use "java.sql.PreparedStatement" object instead of "java.sql.Statement" object.

java.sql.Statement(I)
                |
java.sql.PreparedStatement(I)

"Note: Statement is relatively faster than PreparedStatement."


--to get the PreparedStatement object we need to call "prepareStatement(String sql)" method on the Connection object, with the value or without the value.

--in case of without the value, we need to use placeholders (?)

ex:

	PreparedStatement ps=  conn.prepareStatement("insert into student values(40,'mukesh', 900)");

	PreparedStatement ps=  conn.prepareStatement("insert into student values(?,?,?)");


--In case of Placeholders, before executing the query we need to bind the appropriate values to the corresponding placeholders by calling various types of "setXXX(--)" methods on the PreparedStatement object.
- here XXX will replace with appropriate data type of the value.

Example:

For Integer:-	ps.setInt(1, 50);
For String:-	ps.setString(2,"Amit");
and so on..


--after binding the appropriate placeholders we need to execute the query by using one of the following methods of the PreparedStatement object.

public int executeUpdate();   // if dml 

public ResultSet executeQuery() // if drl 

public boolean execute(); // any type of sql

Note: ResultSet object structure will depends upon the query what we have executed, if does not depends upon the table structure.

 Query:-
 select * from student;

 ALR (After Last Row)->
                     
                   

Now we need to move the cursor from the BFR to the record area, and fetch the data from each column(cell).

--to move the cursor from the BFR to the record area we have a method in the ResultSet object :-

	public boolean next(); // it will move the cursor to the record area and if any record is there then it 				returns true  and if it points to the ALR then it returns false.


--to access/get the column/cell value, from the cursor pointed record area we need to use following methods of the ResultSet object.

	public XXX getXXX(String columnName);  // here XXX will replace with appropriate data type of the value.

Example:-

public int getInt("roll");
public String getString("name");
public int getInt("marks");

-- Here we can also use column index:-

Example:-

public int getInt(1); // for roll
public String getString(2); //for name
public int getInt(3); // for marks



Note: to move the cursor from the BFR to the record area we need to follow following strategy:

1. If we sure that only 0 or 1  record will be there (utmost 1) : in that case we should use "if-else" condition.
(when our search condition in on the Primary key)
 
2. if there may be a chance of getting more than 1 record then we need to use "while loop".

Basic Difference Between Statement and PreparedStatement
========================================================
Statement				PreparedStatement
----------				-----------------
Used for simple/static queries		Used for dynamic/parameterized queries
Query written directly			Uses ? placeholders
Less secure				More secure
Vulnerable to SQL Injection		Prevents SQL Injection
Query compiles every time		Query compiles only once
Slower					Faster (For repeated query)
String concatenation required		No concatenation required
Rarely used in real projects		Mostly used in industry



Internal Working Difference
=-=-=-=-=-=-=-=-=-=-=--=-=-=
Statement
----------
Every time:
	Parse
	↓
	Compile
	↓
	Execute

PreparedStatement
------------------
	Parse + Compile once
	↓
	Set values
	↓
	Execute multiple times

Use Statement when:-
-------------------
- query fixed
- no user input
- simple query

Example:- select * from Student;

Use PreparedStatement when:-
---------------------------
- user input involved
- insert/update/delete operations
- dynamic values
- repeated execution
- security important




ResultSetMetaData:-
==================
- ResultSetMetaData is an interface in JDBC used to get information about the columns of a ResultSet object.

Meaning of Metadata
	Metadata Means Data about data

Example:-
Actual Data
------------
	id	name	marks
	101	Rahul	85
Metadata:-
---------
- Column Names
- Column Count
- Column Types
- Table Name

Package
-------
	java.sql.ResultSetMetaData

Why Do We Use ResultSetMetaData?
--------------------------------
We use it to get:
- total columns
- column names
- column data types
- table name

How to Create ResultSetMetaData Object?
--------------------------------------
Step 1 → Execute Query
	ResultSet rs = st.executeQuery("select * from student");

Step 2 → Get Metadata Object
	ResultSetMetaData rsmd = rs.getMetaData();

Important Methods of ResultSetMetaData
--------------------------------------
Method					Purpose
-------					--------
getColumnCount()			Returns total columns
getColumnName(int column)		Returns column name
getColumnTypeName(int column)		Returns data type
getTableName(int column)		Returns table name
isNullable(int column)			Checks null allowed or not


Example 
--------
public class Demo {
	public static void main(String[] args) {
		try {
			Class.forName("com.mysql.cj.jdbc.Driver");
		} catch (ClassNotFoundException e) {
			System.out.println(e);
		}
		String url = "jdbc:mysql://localhost:3306/Chitkara";
		try(Connection con = DriverManager.getConnection(url,"root","root")){
			PreparedStatement ps = con.prepareStatement("select * from Student");
			ResultSet rs = ps.executeQuery();
			ResultSetMetaData rsmd = rs.getMetaData();
			
			int numberOfColumn = rsmd.getColumnCount();
			System.out.println("Total column numbers :-"+numberOfColumn);
			
			System.out.println("==================");
			
			for(int i=1; i<=numberOfColumn; i++) {
				System.out.println(rsmd.getColumnName(i));
			}
			System.out.println("=============================");
			System.out.println(rsmd.getTableName(1));
		}catch(Exception e) {
			
		}
	}
}

Types of Driver:-
===============

1. Type 1 Driver :- JDBC-ODBC Bridge Driver
===========================================
	- Type 1 Driver is a JDBC driver that converts JDBC calls into ODBC calls and then communicates with the database.

Simple Understanding:-
---------------------

Java application can not communicate directly with the database

First:
	JDBC request converted into ODBC request.

Then:
	ODBC communicate with the database.

What is ODBC?
- ODBC Full Form "Open Database Connectivity"
- It is a Microsoft technology used for database communication.

Architecture of Type 1 Driver
------------------------------
Java Application
↓
JDBC API
↓
Type 1 Driver
↓
ODBC Driver
↓
Database

Internal Working (Step-by-Step)
-------------------------------

Step 1 → Java Application Sends JDBC Calls
	Suppose Java code:
		Statement st = con.createStatement();
Java application send request to JDBC API.

Step 2 → Type 1 Driver Receives JDBC Calls
	Type 1 driver receives JDBC calls.

Step 3 → JDBC Calls Converted into ODBC Calls
	Driver internally:
		JDBC → ODBC
Because database do not understand JDBC directly.

Step 4 → ODBC Driver Communicates with Database
	ODBC driver: database-specific communication.

Step 5 → Database Processes Request
	Database:
		- executes query
		- prepare result 

Step 6 → Response Travels Back
	Database
	↓
	ODBC Driver
	↓	
	Type 1 Driver
	↓
	Java Application

Important Observation
- There are two conversions happens here, that is why performance is slow.
	JDBC → ODBC
	ODBC → Database


Advantages of Type 1 Driver
- Easy to Use
- Good for Learning 
- Supports Multiple Databases

Disadvantages of Type 1 Driver
- Very Slow
- Platform Dependent 	
	- ODBC installation required
	- for Different OS needs different setup.
- ODBC Driver Installation Required
- Not Pure Java
- Removed After Java 8
	- Modern Java versions does not support Type 1 Driver

Why Type 1 Driver Became Obsolete?
----------------------------------

- slow
- complex
- platform dependent
- external setup required
- Industry wanted pure Java solution.



Type 2 Driver - Native API Driver
=================================
Type 2 Driver is a JDBC driver that converts:
	- JDBC calls → Native Database API calls
	- using database-specific native libraries.

What is Native API?

Native API means database vendor ki special system libraries/files.

Architecture of Type 2 Driver
-----------------------------
Java Application
↓
JDBC API
↓
Type 2 Driver
↓
Native Database Library
↓
Database

Internal Working (Step-by-Step)
--------------------------------
Step 1 → Java Application Sends JDBC Calls
	Suppose Java code:
		PreparedStatement ps = con.prepareStatement(query);

Step 2 → Type 2 Driver Receives JDBC Calls
	Type 2 Driver: JDBC requests receive

Step 3 → JDBC Calls Converted into Native API Calls

Step 4 → Native Library Communicates with Database

Step 5 → Database Executes Query

Step 6 → Response Travels Back
	Database
	↓
	Native Library
	↓
	Type 2 Driver
	↓
	Java Application


Advantages of Type 2 Driver
- Faster Than Type 1 
- Better Performance 
- Database-Specific Optimization
- More Efficient Than Bridge Driver

Disadvantages of Type 2 Driver
- Native Library Required - we need to install Database-specific files.
- Platform Dependent 
- Installation Complex 
- Not Pure Java 
- Portability Issues - Different setup for different Machine

Why Type 2 Driver Became Less Popular?
-------------------------------------
Because industry wanted:
- pure Java
- simple deployment
- platform independence


Type 3 Driver - Network Protocol Driver
=======================================
Type 3 Driver is a JDBC driver that uses middleware server to communicate between Java application and database.

What is Middleware?
-------------------
- Middleware means is a server/system which handle communication between Java application and Database.

Architecture of Type 3 Driver
-----------------------------
	Java Application
	↓
	JDBC API
	↓
	Type 3 Driver
	↓
	Middleware Server
	↓
	Database

Internal Working (Step-by-Step)
Step 1 → Java Application Sends JDBC Calls
- Suppose Java code:
	Statement st =	con.createStatement();

Step 2 → Type 3 Driver Receives JDBC Calls

Step 3 → Driver Sends Request to Middleware Server

Step 4 → Middleware Processes Request
- Middleware understand request and convert it into database-specific format.

Step 5 → Middleware Communicates with Database

Step 6 → Database Executes Query

Step 7 → Response Travels Back
	Database
	↓
	Middleware Server
	↓
	Type 3 Driver
	↓
	Java Application

Why Type 3 Driver Was Introduced?
----------------------------------
Because industry wanted:
- platform independence
- no native libraries
- centralized communication

Advantages of Type 3 Driver
- Platform Independent - Pure Java based.
- No Native Library Required 
- Supports Multiple Databases
- Centralized Database Management
- Better Security - Database does not exposed to clint directly.
- Good for Large Enterprise Applications

Disadvantages of Type 3 Driver
1. Middleware Server Required
2. Complex Architecture 
3. Network Dependency 
4. Performance Slower Than Type 4


Type 4 Driver - Thin Driver
===========================
- Type 4 Driver is a JDBC driver that directly communicates with the database using database-specific protocol.
- It is also called Pure Java Driver or Thin Driver
- In Type 4 Driver Java application communicates directly to the database.
- No need of:
	- ODBC
	- native libraries
	- middleware server

Architecture of Type 4 Driver
-----------------------------
	Java Application
	↓
	JDBC API
	↓
	Type 4 Driver
	↓
	Database

Internal Working (Step-by-Step)
-------------------------------
Step 1 → Java Application Sends JDBC Calls
- Suppose Java code:
	PreparedStatement ps =	con.prepareStatement(query);

Step 2 → Type 4 Driver Receives JDBC Calls

Step 3 → Driver Converts JDBC Calls into Database Protocol

Step 4 → Direct Communication with Database

Step 5 → Database Executes Query

Step 6 → Response Travels Back
	Database
	↓
	Type 4 Driver
	↓
	Java Application

Important Observation
----------------------
Type 4 Driver mein:
- no extra conversion
- no middleware
- no native library
So:
- communication is fastest.

Why Type 4 Driver Became Most Popular?
--------------------------------------
Because industry wanted:
- high speed
- simple setup
- platform independence
- pure Java solution

Example of Type 4 Driver
-------------------------
MySQL Driver - mysql-connector-j.jar

Advantages of Type 4 Driver
---------------------------
- Fastest Driver
- Pure Java 
- Platform Independent
- Easy Setup 
- No Middleware Required
- No Native Libraries Required
- Portable
- Industry Standard
	- Nowadays almost all JDBC applications use Type 4 Driver.

Disadvantages of Type 4 Driver:-
-------------------------------
- Database-Specific Driver Required
- Driver Depends on Database Vendor 

Why We Use Type 4 Driver in Modern JDBC?
----------------------------------------
Because:
- best performance
- easy deployment
- pure Java
- platform independent
- simple architecture



DAO Pattern:-
===========
Data Access Object

- DAO is used to keep database code separate from the main application code.
or we can also say that
- DAO (Data Access Object) is a design pattern used to write database-related code in a separate and structured manner.

What Happened Before DAO?
------------------------
- developers used to write everything in a single class:
	SQL queries
	connection code
	ResultSet code

Problems Before DAO
-------------------
1. Code Became Messy
2. Difficult Maintenance 
3. Code Reusability Poor 
4. Large Projects Difficult

DAO introduced because:
-----------------------
- we need to separate database code 
- clean architecture 
- reusable code 

After DAO:-
=========
Code divide properly :-

Layer			Responsibility
----------		---------------
Main Class		Business Logic
DAO			Database Operations
DBConnection		Connection Logic
Entity Class		Data Representation

Note:- DAO is not only a class, it is a design pattern used to organize database code in a clean and structured way.

import java.util.List;

public interface EmployeeLogicInterface {
	
	String addEmployee(Employee emp);
	Employee getEmployeeByID(int id);
	String deleteEmployeeByID(int id);
	List<Employee> getEmployeeList();

}

LOGIC IMPLEMENTATION CODE:-
=-=-=-=-=-=-=-=-=-=-=-=-=

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.util.ArrayList;
import java.util.List;


public class EmployeeLogicImpl implements EmployeeLogicInterface{

	@Override
	public String addEmployee(Employee emp) {
		String message = "Duplicate Employee, already available in Database";
		try(Connection conn = DatabaseConnection.provideConnection()){
			PreparedStatement ps = conn.prepareStatement("insert into Employee values(?,?,?,?)");
			ps.setInt(1, emp.getEmpID());
			ps.setString(2, emp.getName());
			ps.setString(3, emp.getDepartment());
			ps.setInt(4, emp.getSalary());
			int x = ps.executeUpdate();
			if(x>0) {
				message = "Employee added successfully";
			}
		} catch (Exception e) {
			System.out.println(e);
		}
		
		return message;
	}

	@Override
	public Employee getEmployeeByID(int id) {
		Employee emp = new Employee();
		try(Connection conn = DatabaseConnection.provideConnection()){
			PreparedStatement ps = conn.prepareStatement("select * from Employee where empId = ?");
			ps.setInt(1, id);
			ResultSet rs = ps.executeQuery();
			if(rs.next()) {
				emp.setEmpID(rs.getInt("empId"));
				emp.setName(rs.getString("name"));
				emp.setDepartment(rs.getString("department"));
				emp.setSalary(rs.getInt("salary"));
			}else {
				emp=null;
			}
		} catch (Exception e) {
			System.out.println(e);
		}
		return emp;
	}

	@Override
	public String deleteEmployeeByID(int id) {
		String message = "Employee is not available in Database";
		try(Connection conn = DatabaseConnection.provideConnection()){
			PreparedStatement ps = conn.prepareStatement("delete from Employee where empId = ?");
			ps.setInt(1, id);
			int x = ps.executeUpdate();
			if(x>0) {
				message = "Employee removed from the Database";
			}
		} catch (Exception e) {
			System.out.println(e);
		}
		
		return message;
	}

	@Override
	public List<Employee> getEmployeeList() {
		List<Employee> empList = new ArrayList<Employee>();
		try(Connection conn = DatabaseConnection.provideConnection()){
			PreparedStatement ps = conn.prepareStatement("select * from Employee");
			ResultSet rs = ps.executeQuery();
			while(rs.next()) {
				Employee emp = new Employee();
				emp.setEmpID(rs.getInt("empId"));
				emp.setName(rs.getString("name"));
				emp.setDepartment(rs.getString("department"));
				emp.setSalary(rs.getInt("salary"));
				
				empList.add(emp);
			}
		} catch (Exception e) {
			System.out.println(e);
		}
		
		
		return empList;
	}

}

import java.util.List;
import java.util.Scanner;

public class Application {
	public static void main(String[] args) {
		EmployeeLogicInterface el = new EmployeeLogicImpl();
		Scanner sc = new Scanner(System.in);

		while (true) {
			System.out.println("Welcome Emplyee Management System");
			System.out.println("1. Add Employee");
			System.out.println("2. Get Employee By ID");
			System.out.println("3. Delete Employee By ID");
			System.out.println("4. Get All Emplyoee List");
			System.out.println("5. Exit");
			System.out.println("======================================");
			System.out.println("Choose your option:- ");
			int choice = sc.nextInt();

			switch (choice) {
			case 1: {
				System.out.println("Please provide Employee ID");
				int id = sc.nextInt();
				sc.nextLine();
				System.out.println("Please provide Employee name");
				String name = sc.nextLine();

				System.out.println("Please provide Employee Department");
				String department = sc.next();

				System.out.println("Please provide Employee Salary");
				int salary = sc.nextInt();

				Employee emp = new Employee(id, name, department, salary);
				String mess = el.addEmployee(emp);
				System.out.println(mess);
				break;
			}
			case 2: {
				System.out.println("Please provide Employee ID");
				int id = sc.nextInt();

				Employee emp = el.getEmployeeByID(id);
				if (emp == null) {
					System.out.println("There is no any Employee available in Database with id " + id);
				} else {
					System.out.println(emp);
				}
				break;
			}
			case 3: {
				System.out.println("Please provide Employee ID");
				int id = sc.nextInt();
				String mess = el.deleteEmployeeByID(id);
				System.out.println(mess);
				break;
			}
			case 4: {
				List<Employee> empList = el.getEmployeeList();
				if (empList.size() == 0) {
					System.out.println("There is no any Employee available in Database yet...");
				} else {
					for (Employee emp : empList) {
						System.out.println(emp);
					}
				}
				break;
			}
			case 5: {
				System.out.println("Thanks for using our application...");
				System.exit(0);
			}
			default:
				throw new IllegalArgumentException("Unexpected value: " + choice);
			}

		}

	}
}
